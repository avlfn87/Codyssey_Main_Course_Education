1. LM 모델 비교와 선정 보고서
- 같은 과업 프롬프트를 세 종 이상의 모델에 입력하고, 결과를 같은 기준으로 비교해 정리한 보고서이다.
- 비교표와 선정 결론으로 구성한다. (자세한 내용은 '4. 기능 요구 사항' 참고)
- 비교 대상 모델 3종 이상의 이름, 버전, 실행 시점
- 모델별 결과를 같은 기준에 놓고 비교한 표와 그 표에 세운 비교 기준 4개 이상
- 비교 기준마다 매긴 모델별 점수와 그 점수의 근거
- 최종 선정 결론과 선정 근거를 작성한 문장
- 비교 대상 가운데 무료 요금제로 사용할 수 있는 모델이 하나 이상이라는 표시

2. 시스템 설계 문서   
- 페르소나, 시스템 프롬프트, 예시, 검증 전략, 개선 이력을 한곳에 모은 설계 기록이다.
- 항목마다 제목을 붙여 각 부분의 내용을 구분할 수 있게 작성한다.
- 타겟 사용자와 업무 문제를 작성한 문장
- 페르소나와 시스템 프롬프트 전문
- Few-shot 예시 3건 이상과 그 가운데 모호한 입력에 되묻는 흐름 1건
- Zero-shot으로 시도한 결과와 Few-shot 적용 결과를 비교한 기록, 단계적 추론 유도 추가 여부
- 서로 구분되게 실은 시스템 프롬프트, 유저 프롬프트, 입력 템플릿
- 그대로 복사해 다시 쓸 수 있는 입력 템플릿 1개 이상
- 환각 검증 질문 5건 이상과 질문마다 기록한 Pass 또는 Fail 판정
- 서로 구분되게 실은 프롬프트 v1과 v2, v2에서 수정한 내용과 이유에 대한 설명
- 카테고리를 구분되게 표시한 프롬프트 3건 이상

3. 실행 로그
- 설계한 프롬프트로 실제 대화를 수행한 기록이며, 미션을 수행하는 동안 진행한 작업도 함께 남긴다.
- 대화 전문은 편집하지 않고 그대로 기록한다.
- 10턴 이상의 대화 전문과 턴마다 User: 또는 AI:로 적은 화자 표기
- 대화 중간에 조건을 바꾸거나 추가 정보를 준 부분
- 동일한 입력을 두 차례 이상 반복해 결과가 같은지 확인한 구간
- 환각이 발생한 곳과 문맥이 끊긴 곳에 남긴 표시
- 수행한 작업을 항목으로 나누어 적은 작업 기록

4. 미해결 기록
- 프롬프트로 원하는 결과를 얻지 못한 과업을 남긴 기록이다.
- 과업마다 항목을 나누어 작성한다.
- 어려움을 겪었던 과업 2건 이상
- 과업마다 시도한 프롬프트 원문
- 과업마다 직접 작성한 막힌 이유

1. 과업 선정과 정의
자기 업무에서 반복되는 과업 하나를 정해 문장으로 적고, 그 과업의 타겟 사용자, 입력 데이터 형태, 출력 규격을 함께 적는다.
이미 정의해 둔 과업 정의가 있으면 참고하고, 없으면 미션 안에서 새로 정한다.

2.  모델 3종 비교
세 종 이상의 모델에 같은 과업 프롬프트를 입력하고 결과를 모은다.
비교 기준을 4개 이상 세우고 기준마다 모델별 점수와 근거를 적는다.
세 종 가운데 하나 이상은 무료 요금제로 쓸 수 있는 모델로 정한다.

3. 페르소나 설계
페르소나가 다룰 업무 문제를 문서에 문장으로 적는다.
페르소나에 이름, 역할, 전문 분야, 말투, 금지 사항, 우선순위 여섯을 담는다.
